---
name: design-rating-scorecard
description: Score an interface systematically across hierarchy, spacing, typography, color, interaction, accessibility, responsiveness, coherence, and anti-slop quality.
---
Use when the user wants a design rating, launch-readiness score, before/after comparison, or an objective critique.

Score each dimension 0-10 and justify the score with observable evidence:
- visual hierarchy;
- spacing/rhythm;
- typography;
- color/contrast;
- component coherence;
- interaction feedback;
- accessibility;
- responsive behavior;
- content clarity/domain language;
- originality vs generic AI-template patterns.

Rules:
1. Define what a 10 means for this product before scoring.
2. Do not reward novelty that harms task efficiency or accessibility.
3. Distinguish structural issues from cosmetic polish.
4. Assign severity and effort to each gap.
5. Identify the 3 changes with highest expected value rather than producing a giant unprioritized list.
6. If screenshots or a renderer are available, use them; source code alone cannot prove visual quality.
7. For before/after comparisons, use the same criteria and viewport/state.

Output: total score, per-dimension scores, blocking issues, top improvements, and what already works well enough to preserve.
