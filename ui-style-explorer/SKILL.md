---
name: ui-style-explorer
description: Explore and compare multiple visual systems before selecting one, without committing the codebase to a random style prematurely.
---
Use when the user wants alternatives, moodboards, aesthetic directions, or help choosing a visual system.

1. Start from product type, audience, brand, accessibility, platform, content density, and operational context.
2. Propose 3-5 genuinely different directions, not palette swaps of the same template.
3. For each direction specify: typography, palette, spacing density, radius/depth, layout grammar, imagery/icon treatment, and motion.
4. Explain tradeoffs: readability, implementation cost, performance, accessibility risk, maintainability, and fit for the product.
5. Keep examples grounded in the actual task; never invent fake metrics or product functionality to make a style look complete.
6. When one direction is selected, convert it into semantic tokens and reusable patterns before implementation.
7. Do not mix incompatible style families after selection unless the user explicitly wants a hybrid and the combination has a coherent rationale.

This is an exploration skill. It does not override an established design system unless the task is explicitly to replace or evolve it.
