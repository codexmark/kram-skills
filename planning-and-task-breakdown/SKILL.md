---
name: planning-and-task-breakdown
description: Break work into independently verifiable steps with the risky unknowns first.
---
For any task needing 3+ steps:

1. Write the plan before the first edit — each step small enough to verify on its own, each with its own "done" evidence.
2. Front-load the unknowns: the step most likely to invalidate the plan runs FIRST, not last.
3. Sequence by dependency, not by comfort. Parallelize only steps that share no files.
4. Update the plan as reality answers back — a plan that survived contact with the code unchanged was not a plan, it was a hope.
5. Track status honestly: in_progress before starting a step, completed immediately after its evidence exists.
