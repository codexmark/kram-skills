---
name: design-sprint
description: Run a compressed design-sprint workflow to frame a problem, generate alternatives, decide, prototype, and validate before committing to a costly build.
---
Use when the user asks for a design sprint, ideation workshop, concept validation, or a fast structured decision process.

Five phases:

1. **Understand** — define the challenge, actors, constraints, current journey, long-term goal, sprint questions, and measurable risk.
2. **Sketch** — generate several materially different solution concepts. Separate ideation from evaluation.
3. **Decide** — compare concepts against goals, evidence, constraints, accessibility, technical feasibility, and risk. Record why the winner was chosen.
4. **Prototype** — build the smallest realistic artifact that can test the critical assumption; do not overbuild production architecture for a disposable prototype.
5. **Test** — define representative tasks, expected observations, failure signals, and next decisions.

Rules:
- a sprint is not five calendar days unless the user needs that cadence; preserve the phases, not the ceremony;
- do not fake user-testing results;
- unresolved assumptions remain explicit;
- end with a decision: proceed, revise, run another experiment, or stop.
